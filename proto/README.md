# Proto Definitions

gRPC service and message definitions for the optional gRPC adapter. The Kernel
base profile does not start a gRPC server; select the gRPC overlay when that
transport is needed. The protocol sources are authoritative, with generated
Python SDK stubs checked into the repository and service bindings also built
into the legacy gRPC image.

## Directory Structure

```
proto/
├── buf.yaml              Buf v2 module config (lint + breaking change detection)
├── buf.gen.yaml          Buf code generation config (Python + TypeScript SDKs)
├── common/
│   └── pagination.proto  Shared PageRequest/PageResponse messages
├── data/v1/
│   ├── service.proto     DataService — IRI, content hash, resolver, attestor RPCs
│   └── types.proto       IRI, IRIInfo, ContentHashEntry, Resolver, AttestorEntry messages
└── ecocredit/v1/
    ├── service.proto     EcocreditService — classes, batches, balances, baskets, marketplace RPCs
    └── types.proto       CreditClass, Batch, Balance, Basket, SellOrder, and related messages
```

## Code Generation

### Legacy gRPC Docker Build

`Dockerfile.grpc` compiles service bindings at build time and copies them into
`services/grpc/` inside that image:

```dockerfile
RUN python -m grpc_tools.protoc \
    -I proto \
    --python_out=sdk/python/generated \
    --grpc_python_out=sdk/python/generated \
    proto/common/pagination.proto \
    proto/data/v1/types.proto proto/data/v1/service.proto \
    proto/ecocredit/v1/types.proto proto/ecocredit/v1/service.proto
```

The namespaced SDK output in `sdk/python/kokonut/grpc/` is committed and is
regenerated by `scripts/generate-python-sdk-protos.py`. The legacy gRPC image
also creates generated modules under `sdk/python/generated/` and copies its
service imports into `services/grpc/` inside the image. Do not treat the
legacy Docker generation layout as the Kernel default.

### Local SDK Generation (buf)

For local development or the TypeScript SDK's generated-source tree:

```bash
cd proto
buf generate
```

Requires `buf` CLI installed. Generates to `sdk/python/generated/` and `sdk/typescript/generated/`.

## Linting

```bash
cd proto
buf lint
```

Uses STANDARD + COMMENTS rules with exceptions for `UNARY_RPC` and `COMMENT_FIELD`.

## Relationship to services/grpc/

The Python service implementations (`data_service.py`, `credit_class_service.py`)
import generated `_pb2` modules from `services/grpc/data/v1/` and
`services/grpc/ecocredit/v1/`. The legacy `Dockerfile.grpc` populates these
directories in its image at build time.

If generated files are missing (local development without Docker), the server starts anyway — service registration is wrapped in `try/except ImportError`.

## Adding New RPCs

1. Add the RPC and messages to the appropriate `service.proto` and `types.proto`
2. Implement the method in `services/grpc/data_service.py` or `services/grpc/credit_class_service.py`
3. The method signature must match: `def MethodName(self, request, context):`
4. Regenerate/verify the SDK bindings and rebuild the selected gRPC image. For
   the legacy stack, use `docker compose build grpc`; for Kernel, use the
   planner's printed `--grpc` overlay command.
