## 1. How to read this baseline

- **Source present** means implementation or configuration was inspected in this repository. It does not prove a service is running or that the behavior works end to end.
- **Test reference** means a relevant test file exists. Unless called out explicitly, tests were not executed in this Phase 0 pass.
- **Runtime unverified** means deployment, external clients, provider credentials, live data, or recovery behavior still needs a controlled test.
- A directory under `services/` is not automatically a daemon. Many modules are libraries or command-line workflows; they become runtime dependencies only when a process, scheduler, event handler, or other caller invokes them.
- The inspected source baseline originally included Metabase in default Compose. A follow-on repository-only change moves it to an opt-in profile and removes default Caddy routes; this does not remove dashboard assets, alter the Metabase database/volume, start services, deploy Staging, or authorize data disposition.

## 3. Dependency and data-flow map

### Canonical ownership domains

[`docs/data-model/domain-ownership.md`](data-model/domain-ownership.md) assigns technical ownership of canonical tables, services and migrations to domains. At a high level:

- **Identity and stakeholders:** `party`, farmer profiles/credentials/KYC, organization membership, consent, engagement and grievance records.
- **Farm operations:** locations, farms, plots, crop cycles, harvest and operational events, labor, inventory and files.
- **Environmental measurement and impact:** soil, species, sensors, weather, remote sensing, baselines, MRV claims and reviews; carbon/ecological outputs.
- **Metrics and modeled outputs:** definitions, versions, computed values, snapshots and scorecards. Computation and independent verification are separate.
- **Finance and credits:** financial/marketplace records, credit classes/batches/balances/retirements and certificates.
- **Governance, strategy and workflow:** governance frameworks, plans, decisions, threatcasting/backcasting, Delphi, lifecycle and approval records.
- **Platform/integration records:** API keys/capabilities, event/scheduler state, IRIs/content hashes, federation and attestation indexes.

This is *technical domain ownership*, not a named human RACI. Repository docs do not assign a primary operator, service owner, backup custodian, or independent reviewer by domain. Named owners must be agreed before a Staging pilot or Production launch.

### Network and protocol boundaries observed in repository configuration

- PostgreSQL and ClickHouse are internal-network services in base Compose; no host port is declared for either.
- Directus has a loopback-default host mapping, Redis is internal, and MQTT is loopback-bound. gRPC is loopback-bound in base Compose and loses the host mapping in the production overlay.
- Base Compose's Gateway host mapping defaults to `0.0.0.0:8099`; production removes that mapping. Validate this default before using development Compose on a shared/public host.
- The inspected baseline Caddyfiles routed `/metabase/*`; the follow-on Compose change removes that route from both default Caddyfiles. Current routes include `/directus/*`, `/admin/*`, `/maps/*`, `/field/*`, `/mobile*`, `/api/mobile/*` and `/grpc/*`; fallback is Directus. Both repository Caddyfiles show an h2c gRPC upstream path. This is a configured proxy path, not proof of a working client transport or authorization boundary.
- The HTTP sensor receiver and MQTT subscriber are callable processes, not services in the base Compose list. Scheduler, event, Prefect and agent definitions likewise must be tied to an actual worker/dispatcher before counting them as active runtime dependencies.

## 4. Secrets, operators and recovery controls

### Secret classes (names/values intentionally not enumerated)

- SOPS-encrypted per-environment application configuration; age private keys remain outside source control and on authorized runtime/secret-management surfaces.
- Runtime credentials for PostgreSQL, Redis, ClickHouse, Directus, Gateway API keys/capabilities, gRPC API keys, MQTT client identity/HMAC, external data providers, EAS/RPC and model providers.
- `BACKUP_ENCRYPTION_KEY` protects database/ClickHouse checkpoint artifacts. Losing it makes encrypted checkpoints unusable.
- TLS materials for Caddy, gRPC (optional in server code), MQTT broker and sensor clients.

No secret file contents or live environment values were read for this baseline. The documented SOPS approach protects repository values at rest; it does not protect values from runtime/container inspection. A per-service secret inventory, least-privilege grants, rotation ownership, emergency revocation process and break-glass recovery owner remain to be assigned.

### Backup/restore evidence and limitations

- `scripts/backup.sh` defaults to PostgreSQL database `kokonut_intelligence`, exports ClickHouse schema/table data, encrypts the resulting database artifacts and writes checksums/manifest. It does **not** archive the Directus uploads, Metabase application database/volume, Mosquitto data, or Caddy volumes in its inspected default path.
- `scripts/verify-backup.sh` checks manifest presence, non-empty files and SHA-256 equality. It does not decrypt artifacts or perform a restore.
- `scripts/restore.sh` requires explicit `--confirm`, decrypts and restores PostgreSQL dumps and ClickHouse exports into the configured targets. It does not restore the file/broker/proxy volumes listed above. Run only against a disposable, isolated project/database for rehearsal.
