KI's PostgreSQL/PostGIS + Directus layer is the canonical operational record; ClickHouse remains analytical/event storage. The mapping follows the repository schema, not a spreadsheet-shaped mirror. Source links must resolve through a stable crosswalk, never by display text alone.

- Keep forecast, plan, actual, evidence, verification, and publication as distinct concepts. A legacy label or free-text `Impact Verification` field does not establish evidence review or verification.

- Exclude formulas, lookups, rollups, counts, autonumbers, and Baserow audit/system columns from direct import. Recompute derived values in KI only where a canonical definition exists.

- This is a schema-level crosswalk. A candidate target means “schema shape is plausible,” not that source values, units, enums, or business meaning have passed row-level review.

## 4. Duplicate and conflict policy

No semantic duplicate merge is approved by this schema-only review. Before a dry-run import, build a report of candidate duplicates using table-specific, human-reviewed natural keys. Do not use display name alone except as a *candidate* for review.

1. **Exact source identity:** same composite provenance key is an idempotent replay. Same source key with changed source projection hash is a source-version conflict; stop and review rather than overwrite.
2. **UUID collisions:** treat source UUID as table-scoped. A UUID collision across different Baserow tables is not a duplicate; duplicate/missing UUID within a source table is blocking.
3. **Natural-key candidates:** identify candidates separately per entity (for example, municipality + province for locations; farm + plot name for plots; task title + farm + start date for tasks; date + entity + category + amount + reference for expenses). These keys are review heuristics, not merge rules; recurring legitimate records can share values.
4. **Canonical collisions:** if a target row already exists, do not overwrite it. Compare provenance, normalized key, field projection, lifecycle, and evidence; route ambiguous collisions to a human decision queue.
5. **Conflicting values:** never “last write wins.” Record source key, target key, field, both values in the restricted reconciliation workspace, selected resolution, reviewer, timestamp, and rationale. Only the approved fields may move into the target.
6. **Human-reviewed lifecycle:** migration never marks a record verified or published. Rejected or conflicting rows remain quarantined for correction; no record is dropped without a disposition reason.
